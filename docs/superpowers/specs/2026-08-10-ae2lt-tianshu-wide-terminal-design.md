# AE2LT 天枢样板终端宽屏兼容设计

日期：2026-08-10

## 背景

AE2 Wide Wireless Terminal 将 AE2 终端存储区扩展为 18 列，并把普通样板编码区和玩家物品栏向右偏移 81 像素，使其在 357 像素宽的终端中居中。

AE2 Lightning Tech 2.0.6 的有线与无线天枢样板终端继承 `MEStorageScreen`，因此存储区和玩家物品栏会采用宽屏布局；但它使用独立的 `Tianshu*EncodingPanel` 和天枢专属样式。普通 AE2 面板的居中 Mixin 不会作用于这些类，天枢专属控件也仍使用 195 像素窄屏坐标，造成上下布局分裂。

## 目标

- 同时适配有线 `TianshuPatternEncodingTermScreen` 和无线 `TianshuWirelessPatternEncodingTermScreen`。
- 宽屏模式下，天枢编码面板、模式页签、倍增按钮、闭环编码控件和样板槽与普通宽屏样板终端使用同一条水平基线。
- 窄屏模式保持 AE2LT 2.0.6 的原始布局。
- 不修改天枢的编码、上传、维护、闭环、JEI 或终端切换逻辑。
- 未安装 AE2LT 时，本 Mod 仍可正常启动。

## 布局

宽屏相对窄屏的水平偏移固定为 `+81`：

- 编码面板：`8 -> 89`。
- 模式面板：`9 -> 90`。
- 模式页签：`173 -> 254`。
- 空白样板与已编码样板槽：沿用宽屏普通样板终端的 `228`。
- 所有天枢专属按钮、滚动条、文本框和闭环面板均在原始横坐标上增加 81。
- 玩家物品栏继续使用宽屏基础终端的 `left = 89`，不做二次偏移。

垂直坐标、控件尺寸和 AE2LT 原始纹理保持不变。

## 实现边界

1. 新增天枢宽屏样式覆盖：
   - `assets/ae2/screens/terminals/tianshu_pattern_encoding_terminal.json`
   - `assets/ae2/screens/wireless_tianshu_pattern_encoding_terminal.json`
2. 新增只针对 AE2LT 四个天枢编码面板的客户端 Mixin，把宽屏时背景绘制横坐标从 8 改为 89；窄屏仍返回 8。
3. Mixin 使用字符串目标类名，避免把 AE2LT 变成强制依赖。
4. `MEStorageScreenMixin` 的宽窄样式路由增加天枢有线与无线终端的专用路径，防止切换宽窄后退回普通 AE2 样板终端样式。

## 失败与兼容处理

- AE2LT 未安装时，兼容 Mixin 必须由可选配置插件或等价的安全加载方式跳过，不允许导致类加载失败。
- 只识别 AE2LT 2.0.6 当前公开的终端类名；其他终端不进入天枢分支。
- 若 AE2LT 后续改变类名或方法常量，Mixin 应明确失败于兼容测试，而不是静默移动错误控件。

## 测试

- 红灯测试先证明当前资源不存在天枢宽屏坐标，且最终包没有天枢面板兼容 Mixin。
- 资源测试逐项验证所有天枢专属横坐标均为原坐标加 81。
- 字节码测试验证四个天枢面板的 `drawBackgroundLayer` 在宽屏时使用 89、窄屏时使用 8。
- 回归测试覆盖普通终端、普通样板终端、无线样板终端和无线通用终端，确保现有布局不变。
- 最终 JAR 检查 AE2LT 未被打入包内，且 NeoForge 元数据、Mixin 清单和 ZIP 路径仍有效。

## 验收标准

- 上方 18 列存储区、下方天枢编码区和玩家物品栏水平居中。
- 天枢所有模式页签和专属按钮不重叠、不越界。
- 宽窄切换后布局立即正确，物品和样板内容不丢失。
- 有线与无线天枢样板终端表现一致。
